# work/ —— 导出工具与中间数据

这个文件夹是导出题库时的工作区。**删掉它不影响已经生成的三个成果文件**，
但删了就没法再重新导出了（这是上次我犯过的错误）。

## 文件说明

| 文件 | 作用 | 重要性 |
|---|---|---|
| `template.html` | 离线题库页面的模板，占位符 `__DATA__` 会被替换成题库数据 | 🔴 必需，**唯一副本** |
| `build.js` | 把 `topics_raw.json` + `meta.json` 填进模板，生成最终 HTML | 🔴 必需 |
| `fetch_topics.js` | 从服务器下载并解密题库，产出 `topics_raw.json` | 🟡 题库更新时才用 |
| `topics_raw.json` | 395 题原始数据（含 `IsAnswer` 答案标志、`Analysis` 解析） | 🟡 可重新下载 |
| `meta.json` | 题库配置 + 你账号的错题/收藏记录 ID | 🟡 可重新下载 |
| `verify/` | 验证过程中产生的临时文件，**可以删** | ⚪ 不重要 |

## 重新导出（题库更新时）

```bash
cd D:\program\题库\work

# 1. 下载最新题库（openid 用环境变量传，不要写进文件）
$env:TIKU_OPENID="你的openid"        # PowerShell
node fetch_topics.js

# 2. 生成 HTML
node build.js
```

`fetch_topics.js` 会做这几件事：
1. 用 `appid` + `openid` 换 token
2. **先检查题库激活状态**——没激活就直接中止（否则只会拿到 10 道试看题，静默产出残缺题库）
3. 下载密文、按 `key=CreationTime+"000000"` / `iv="111111"+CreationTime` 解密
4. 完整性护栏：题数 ≤ 10 就报错中止
5. 更新 `meta.json` 里的错题/收藏记录（自动过滤掉题库里已不存在的题）

`build.js` 会做这几件事：
1. 把题目字段瘦身（原始数据里的 `$id`/`Appid`/`Medias` 等页面用不上）
2. **数据自检**：题干空、选项少于 2 个、没有正确答案、缺解析、单选题多答案、多选题少答案 —— 任何一项不过就中止，不产出坏题库
3. 转义 `<` `>`（否则题库里出现 `</script>` 会截断整个 HTML）
4. 写入 `..\阿里云ACP大模型-离线题库.html`

## ⚠️ 两个必须知道的坑

**1. 服务端返回的题目顺序不稳定**

同一批 395 道题，不同时间抓取，**内容完全相同但排列顺序会变**。
实测：16:27 抓的和 17:28 抓的，395 个 Gid 集合完全一致，但顺序从第 78 题开始分叉。

这意味着：
- 重新导出后，「顺序刷题」的题序可能和上一版不同 —— 这是服务端行为，不是 bug
- 交付的这份 HTML 用的是 16:27 那次抓取的顺序
- 想验证两次抓取是否等价，**要按 Gid 对齐后比内容，不能直接比数组顺序**

**2. openid 是账号凭证，不要写进任何文件**

`fetch_topics.js` 故意不保存 openid，运行时从 `TIKU_OPENID` 环境变量读。
这个值等价于你账号的身份凭证之一，泄露了别人就能用你的账号下载题库。

（我最初是从 `WeChatAppEx.exe` 进程内存里读出来的，那是一次性的本机操作，没有落盘。）

唯一需要留意的是 `topics_raw.json` 里含完整题库内容，如果要分享这个目录给别人，先想清楚。

## 统计与错题排行（2026-10-22）

新增两个标签页：

**统计** — 按题型 / 按难度看各组的已练、正确率、错题数、平均用时。
  题型来自题库原始数据；**难度是推导出来的**（题库没有这个字段），
  规则：历史错过 ≥2 次 → 较难；错过 1 次 → 一般；首次接触耗时 > 平均 1.5 倍 → 较难；
  其余一次就对 → 简单。关键设计：先看历史错次再看本次对错，
  这样「以前错过、今天答对」的题不会被洗成「简单」。

**错题排行** — 按累计答错次数降序，次数相同则最近错的在前。
  错次数**只增不减**（答对也不减），否则就看不出哪些题在反复错。
  支持前 10 / 20 / 50 / 全部，点条目可跳回那道题。

配套改动：

- 新增 `S.wcnt`（gid→累计错次）、`S.wlast`（gid→最后答错时间），随进度一起持久化
- 抽出 `noteWrong(gid)` / `noteRight(gid)`，让「顺序刷题」和「模拟考试」两条路径
  共用同一套计数逻辑，避免改了一处忘了另一处
- 「重做本题」不再清错次（错次是统计依据）；「移出错题本」只移出、保留次数

## 进度会不会丢？（重要）

结论：**正常使用不会丢，但 localStorage 有三个边界要清楚。**

实测过的情况：

| 场景 | 结果 |
|---|---|
| 正常关闭浏览器 / 正常关机重启 | ✅ 进度完整保留 |
| 强杀进程但已过几秒（浏览器已写盘） | ✅ 保留 |
| 答题后瞬间断电（不给写盘时间） | ⚠️ 最后这一题可能丢 |
| 把 HTML 换目录、改文件名 | ✅ 保留（file:// 按「源」共享存储，不看路径） |
| 换一个浏览器（Chrome→Edge） | ➖ 各自独立，不会互相同步 |
| 无痕/隐私模式 | ⚠️ 关掉即丢（浏览器机制，无法绕过） |
| 清浏览器「站点数据」/cookie | ⚠️ 会丢 |
| 换电脑 / 重装系统 | ⚠️ 会丢（数据不在 HTML 文件里） |

已做的加固：
- 每 5 秒自动落盘一次
- `visibilitychange` 页面切走时立刻保存（手机切 App、锁屏）
- `pagehide` + `beforeunload` 双保险（手机上 `beforeunload` 经常不触发，`pagehide` 更可靠）

已做的兜底：**统计页底部有「导出备份 / 从备份恢复」**。
导出一个 JSON 文件，换电脑或数据被清时导回来即可。

自查方法：打开 `chrome://version` 看「个人资料路径」，
你的进度就存在那个目录里的 Local Storage 数据库里。

## 随机刷题：选项位置也打乱（2026-10-22）

「随机刷题」页顶部新增开关：**「选项也打乱 / 只打乱顺序」**，默认打乱。

### 为什么不能简单地 shuffle

这个功能看着简单，但有三个坑，每一个都能让题做错：

**坑 1：选项顺序会绑定答案**
已答过的题记的是选项下标。如果每次渲染都重新打乱，之前记的答案就指向别的选项了。
→ 解决：用 `gid` 哈希当种子，**同一道题永远得到同一个排列**；且存储层一律用「原始下标」，
   只在显示层做映射。这样打乱不影响已存数据。

**坑 2：解析正文用字母指代选项**
题库里有 105 道题的解析写着「A 对」「选项 B」「故选 C」「（A 对）」。
打乱选项后这些字母就指错了，比不打乱更糟。
→ 解决：`remapLetters()` 把解析正文里的选项字母按同一映射重写。

**这里踩过一个真实的坑**：最初写成「一条条正则依次替换」，结果 A→B 之后，
下一条规则又把新出现的 B 改成 C，形成级联替换（A→B→C）。
→ 改法：用**单个正则 + 一次性替换**，全程只扫一遍原文。

**坑 3：有些题的选项不能乱序**
题库里有题的选项是「以上所有」「以上修改方法均不正确」，这类选项逻辑上指向别的选项。
→ 解决：`canShuffleOptions()` 检测到这类文本就保持原顺序。

### 其它细节

- 模拟考试在**开考时**就把每题选项顺序固化到 `E.optOrder`，
  否则交卷后 `examRunning()` 变 false，选项会变回原序，跟考试时看到的不一致
- 打乱后如果恰好等于原序（数学上 4 选项概率 1/24 ≈ 4.2%），会整体旋转一位，
  保证「说打乱了就真的打乱」
- 顺序刷题 / 错题本 / 收藏 / 搜索 **不打乱选项**，方便对照记忆


## 顺序刷题：每次重置换一套选项位置（2026-10-22）

### 需求与实现

顺序刷题原本保持题库原始选项顺序，现在改成**打乱**，而且**每重置一次就换一套排列**。
目的很直接：防止靠「记住答案在第几个」蒙对。

实现方式：选项排列的种子 = `gid 哈希 + S.optRound`。
- `S.optRound`（轮次）在每次点「重置」时 +1
- 不重置时，同一道题永远是同一个排列（刷新、切页面、重开浏览器都不变）
- 重置后整个题库的选项位置一起换

顺序刷题页顶部会显示「第 N 轮 · 选项位置每轮重排」，明确告诉你现在是第几轮。

### 连带影响（这些是必须一起改的）

改成「顺序模式也打乱」之后，有三处会不一致，都处理了：

1. **同一道题跨页面位置必须一致**
   错题本、收藏、搜索 现在与顺序刷题**共用同一套排列**。
   否则同一道题在顺序页是 ABCD、在错题本是 BADC，容易点错。

2. **解析里的字母引用**
   之前顺序模式不重映射解析，现在打乱了就必须重映射
   （`analysisText()` 已统一按 `optionView().shuffled` 判断）。

3. **考试不受轮次影响**
   开考时把每题排列固化进 `E.optOrder`，考试中改轮次也不影响本次考卷。
   测试专门验证了这点。

### 「以上所有」类题仍然不打乱

`canShuffleOptions()` 的检查前置到最前面，这类题任何模式下都保持原顺序。

## 三个专项练习：单选 / 多选 / 错题攻坚（2026-10-22）

### 需求

把题库拆成三条**互不干扰**的练习线，每条线自己记进度：

| 专项 | 题池 | 干什么 |
|---|---|---|
| 单选专项 | 全部 273 道单选题 | 集中刷单选 |
| 多选专项 | 全部 122 道多选题 | 集中刷多选（漏选、多选都算错，是提分重点） |
| 错题攻坚 | 做错过、且还没掌握的题 | 专治反复错的题，连续答对 3 次自动移出 |

每个专项页上都要有：

- **概览卡** —— 三个大数字（已做 / 做对 / 做错）+ 进度条「进度 18/273 · 还剩 255 题没做」
- **控制条** —— 「按题号 / 随机出题」切换、跳转到第 N 题的输入框、「重置本专项」
- **题卡** —— 复用原有题卡，也就是解析、计时、收藏、重做那套全都在

标签页从 9 个变成 **12 个**（`TABS` 里新增 `single` / `multi` / `hard`，插在随机刷题和错题本之间）。

### 掌握度：为什么不是「答对一次就移出错题本」

**这是本功能最重要的设计决定。**

旧逻辑是：答对一次 → 立刻移出错题本。听着合理，实际很糟：
选择题 4 选 1，蒙对的概率就有 25%，错过的题第二次答对**很可能只是蒙对**。
按旧逻辑，一道反复错的题只要蒙对一次就从错题本里消失了，下次考试照样错。
结果是错题本越刷越短、真实水平一点没变 —— 这叫「假掌握」。

所以引入「连续答对次数」`S.streak`（gid → 次数）：

| 事件 | `streak` 变化 | 错题本 |
|---|---|---|
| 答错 | 归零 | 立刻加回去 |
| 答对但不满 3 次 | +1 | 留在里面 |
| 连续答对满 3 次 | — | 移出 |

判定口径只有一个 `MASTER_STREAK = 3`，`isMastered(gid)` 就一句话：`streak >= 3`。
`noteRight()` 里「要不要移出错题本」就是看这个数，`noteWrong()` 里把它清零。

为什么是 3，不是 2 也不是 5：2 次太松（连续蒙对两次仍然有不小的概率），
5 次又刷得太久，攻坚池迟迟不见小，人会放弃。3 次配「答错即归零」
（对 2 次、错 1 次、再从 0 开始），已经能挡掉绝大多数蒙对。

### 三档等级

`masteryOf(gid)` 在掌握度之上再分三档，`drillStats()` 和攻坚页的统计都按这个口径数：

| 等级 | 判定 | 含义 |
|---|---|---|
| 顽固 `stubborn` | `streak === 0 且 wcnt > 0` | 错过、且当前一次都对不上 → 最该先攻 |
| 巩固中 `learning` | `streak` 为 1 或 2 | 对上过，但还不够 3 次 |
| 已掌握 `mastered` | `streak >= 3` | 移出错题本，也不再进攻坚池 |

（另有 `untouched` = 既没作答记录也没错过，用于排除「没碰过」的情况，不算一档。）

攻坚页顶部会多一行「待攻克 N 题 · 其中已连续对 3 次可移出 M 题」。
另外两个专项的池子是固定大小（273 / 122），只有攻坚池会越刷越小 —— 这正是目的。

### 攻坚池到底收哪些题

`drillPool('hard')` = 两个集合的并集：

1. `S.wrong` —— 错题本里现有的题
2. `{ gid | S.wcnt[gid] > 0 且 !isMastered(gid) }` —— 做错过、但已经被手动移出错题本的题

第 2 条看着像多余（「我明明已经把它移出去了」），但它是必须的。

因为「移出错题本」按钮的真实语义是**「我不想再看到它了」，不是「我掌握了」**：
它的实现只是把 gid 从 `S.wrong` 数组里删掉，`S.wcnt`（累计错次）一个字都不动
—— 错次是错题排行页的依据，清掉排行就缺题了。

如果攻坚池只读 `S.wrong`，那手滑点一次「移出」，这道没掌握的题就永远从攻坚名单里消失；
下次考试再错 → 又进错题本 → 又移出，来回循环，永远攻不掉。
所以收题口径必须同时看「历史错次」和「当前掌握度」，**不能只看「在不在错题本里」**。

反过来，一旦连续对满 3 次（`isMastered` 为真），题就自动出池，
所以攻坚池是一个会自己变小的集合 —— 池子空了就是「所有错过的题都真掌握了」。

### 三个专项的进度为什么必须分开

`S.drill` 里给三个专项各存一份四件套：

```js
S.drill = {
  single:{pos:0, order:null, shuffleSeq:false, round:0},
  multi: {...}, hard: {...}
}
```

| 字段 | 作用 |
|---|---|
| `pos` | 当前第几题 |
| `order` | 随机出题时固定下来的题序（`null` = 还没生成） |
| `shuffleSeq` | 按题号 / 随机出题 |
| `round` | 本专项重置过几次，用来换随机种子 |

分开是硬需求，不是洁癖：三个池子大小完全不同（273 / 122 / 会变）。
共用一个 `pos` 的话，在单选专项刷到第 200 题，切到多选专项直接越界（多选只有 122 题）。
随机题序同理 —— 拿单选的 273 条题序去索引多选池，出来的是随机噪声。

`drillList(key)` 的随机种子 = `key.charCodeAt(0) * 7919 + round * 104729`：

- 用 `key` 首字母（`s` / `m` / `h`）区分专项，三个专项天然不同序
- 用 `round` 区分轮次，重置一次换一套
- 算出来的题序存在 `st.order` 里，**同一轮内反复渲染、切页面、刷新浏览器都不变**
  —— 否则「每看一眼就换个顺序」，翻页必然翻丢
- 攻坚池变小（有题掌握了）时，按当前池子再过滤一次，避免题序里挂着已出池的 gid

### 重置本板块：清的是「作答记录」，不是「刷到哪了」（2026-10-22 修）

> ⚠️ 这一节原来写的是「重置的是『刷到哪了』，不是『学过什么』」，
> 并把它当成设计意图。**那个意图是错的**，用户实际用起来就是「按钮坏了」。

#### 缺陷：点了「重置本专项」没反应

原来的 `resetDrill(key)` 只做四件事：`pos = 0`、`order = null`、
`round + 1`、`S.optRound + 1` —— **完全没有碰 `S.ans`**。

但题卡判断「这题做过没有」看的就是 `S.ans[gid]`：

```js
var answered = !!rec;                              // rec = S.ans[q.gid]
var showAns = answered || revealed || S.memorizing;
```

于是重置后每道题仍然 `answered = true`，结果是：

- 进度条回到 0、题号回到第 1 题 ✅
- 可第 1 题**答案和解析直接摊在屏幕上**，选项全是 `locked`，点不动 ❌

所以当时的「重置」实际语义只是「回到第 1 题」，不是「让我重做」。
用户只能改用右上角**总重置** —— 结果连错题本、收藏、成绩走势、错次统计
一起清空，损失大得多。

#### 为什么测试没发现

`verify_drill.js` 里那条断言是这么写的：

```js
check('重置专项不清空答题记录', Object.keys(bank.S.ans).length > 0 || true);
//                                                        ^^^^^^^^ 永远为真
```

`|| true` 让它永远通过，等于没测 —— 而它掩盖的恰好是这个缺陷。
**假通过的断言比没有断言更危险**，因为它会让人以为这块已经验过了。
已改成按真实语义断言「本专项题池内的作答记录必须被清空」。

#### 另外：顺序 / 随机 / 错题本三个板块根本没有本板块重置

只有三个专项页有「重置本专项」，这三个板块想重做只能点总重置。

#### 现在定的语义

「重置」= **让我能把这个板块重新做一遍**，但只影响这个板块。

`resetDrill(key)` / `resetPractice(modeKey)` 统一做两件事：

1. `clearAnsweredIn(题池)` —— 清掉该板块题池里每个 gid 的
   `S.ans` / `S.pend` / `S.reveal`
2. 进度归零 + 换一套选项排列（`S.optRound + 1`）；
   随机刷题额外重抽一次题序 `S.order`

| 清 | 不清 |
|---|---|
| 本板块题池内的 `S.ans` 作答记录 | 其他板块的作答记录 |
| 本板块的 `pos` / 随机题序 | `S.wrong` 错题本名单 |
| 本板块待提交的 `S.pend` | `S.star` 收藏名单 |
| 本板块的单题揭示 `S.reveal` | `S.wcnt` / `S.wlast` 累计错次（排行依据） |
| 换一套选项排列 `S.optRound` | `S.streak` 掌握度（清了攻坚池会自己涨回去） |
| | `S.daily` / `S.examHistory` 成绩走势 |

**为什么错题本、收藏这两个板块的重置不清 `S.wrong` / `S.star`：**
那两个数组**就是**这些板块的题池。清掉它们 = 板块直接空掉 = 功能自毁。
所以它们只清「本题池里的作答记录」，让题能重做，**名单本身保留**。

#### 按钮分布

| 板块 | 按钮 | 位置 |
|---|---|---|
| 顺序刷题 | 重置本轮 | 轮次徽标右边 |
| 随机刷题 | 重置本板块 | 「选项也打乱」开关右边 |
| 错题本 / 收藏 | 重置本板块 | 板块说明右边 |
| 单选 / 多选 / 错题攻坚 | 重置本专项 | 控制条里（原有） |
| 全部 | 重置（总） | 右上角，语义不变：全部清空 |

每个按钮的确认框都写明「会清本板块的作答记录（当前已做 N 题）」和
「不会动错题本/收藏/成绩走势」，并在 toast 里报出清掉几题
（例：`已重置「顺序刷题」，4 题可以重新做了`）——
**提示语要能让人确认按钮真的生效了**，否则「点了没反应」还会被当成 bug。

「只清自己」这种承诺，光验证「自己的清掉了」是不够的。

### 踩过的四个坑

**坑 1：`noteWrong` 不写 `S.ans`，导致「错过一次」被判成「没接触」**

`noteWrong(gid)` 只做四件事：进错题本、`wcnt + 1`、记 `wlast`、`streak = 0`。
它**不碰 `S.ans`** —— 作答记录是答题路径（`submitNow` / 交卷）写的，「记一次错」是另一回事。

于是最初那版 `masteryOf()` 只看 `S.ans[gid]` 判断「碰过没有」，就把
「错过一次、但还没重做过」的题判成了 `untouched`（没接触）——
它明明是最该攻的顽固题，却被归到了「没碰过」那一档。

改法：未接触的判定必须**同时**看两个来源 ——
`if(!rec && c === 0) return 'untouched'`，`rec` 来自 `S.ans`，`c` 来自 `S.wcnt`。
只看其中任何一个都会分错档。

**坑 2：专项进度存在 `S.drill[key].pos`，题卡却只认 `S.pos[modeKey]`**

题卡 `practiceCard()` 原来直接读写 `S.pos[modeKey]`。
可专项模式的 `modeKey` 是 `single` / `multi` / `hard`，`S.pos` 里根本没有这几个键，
写了白写、读了永远是 `0`。

具体现象：跳转框输入 10，`S.drill.single.pos` 确实变成了 9，
但题卡还显示「第 1 / 273 题」—— 看着像跳转没生效，
实际是**进度写对了，读的地方读的是另一个变量**。

改法：加一层映射 `getPos(modeKey)` / `setPos(modeKey, v)`，
里面用 `isDrillMode()` 分流：专项读写 `S.drill[modeKey].pos`，其余照旧读写 `S.pos[modeKey]`；
`practiceCard()` 里所有 `S.pos[...]` 都改成走这对函数。
教训：**一个状态只要有两个来源，就必须只留一个读写入口**，否则下次还会漏掉某一处。

**坑 3：提示语和实际行为不符**

新逻辑是「连续对 3 次才移出」，但 toast 还是老文案：答对一次就弹「已移出错题本」。
用户顺着弹窗去错题本一查，题还在 —— 提示语说假话比不提示更糟。

改法：按当前 `streak` 分三种文案，把「还差几次」直接告诉用户：

| 情况 | 提示 |
|---|---|
| 本来就不在错题本 | 答对了 |
| 刚好连满 3 次 | 连续答对 3 次，已掌握，移出错题本 |
| 还在 1–2 次 | 答对了 · 连续 N/3 次，再对 M 次移出错题本 |

第三种是关键：不写清楚，用户就不明白「为什么我答对了它还在错题本里」。

**坑 4：改 `S` 对象漏了一个逗号，整段脚本编译失败**

给 `S` 加 `streak` / `drill` 时，`drill:{...}` 这段结尾漏了一个逗号，
下一个字段接上去就成了语法错误。而模板是整段脚本塞进 `new Function()` 里跑的：
一处语法错误 = 整个页面白板，控制台只给一句 `Unexpected identifier`，**不告诉你第几行**。

定位方法：把模板里那段脚本抽出来，用 node 逐行 / 逐段 `new Function()` 试探，二分到具体那一段。
不是「大概哪一块」，是真的一行一行试出来的。

还有个连带教训：`node build.js` 跑通**不代表页面没问题** —— 构建只替换数据，不解析脚本。
所以每次动模板脚本，都得跑一遍 jsdom 测试（`verify_drill.js` 最后一项就是「全程无 JS 异常」）。

### 一个会随机失败的测试（已修）

`verify_option_shuffle.js` 曾经**大约 13% 概率随机失败**，报：

```
✗ 点打乱后的正确选项 → 判为正确 :: {"hasResult":false,"cls":null,...}
```

看着像打乱算法有 bug，其实是**测试自己写错了**。

根因：那条断言进「随机刷题」页后，假定当前题是单选题，点一下选项就去断言 `.result`。
但随机刷题的第一题是**随机抽的**，约 1/4 概率抽到多选题，而：

| 题型 | 作答流程 |
|---|---|
| 单选题 | 点中选项 → 立即判分，出现 `.result` |
| 多选题 | 点选项只是勾选 → 必须点「提交」才判分，且**必须选全**所有正确答案 |

于是抽到多选题时：没提交 → 没有 `.result` → 断言失败；
只点了一个正确选项 → 即使提交了也判错（漏选算错）。

改法：按题型分流 —— 多选题勾全所有正确选项再点「提交」，单选题保持原来的一次点击。
验证方式：连续跑 20 次全绿（修之前 15 次里必挂 2 次）。

这个坑值得记的地方在于：**「随机」是测试里的隐性输入**。
凡是测试结果依赖随机抽样（随机刷题、随机出卷、随机选项排列），
就不能假设抽到的是什么，必须先读出来、再按它的类型分别处理。

### 一个容易误判的点：攻坚页的「做对」常年是 0

这不是 bug。

三个数字都是在**当前池子内**数出来的：池子里已作答的题有几道、其中对几道、错几道。
而攻坚池的入池门槛就是「做错过」，所以池子里的题刚进来时全是「做错」状态，
「做对」自然是 0。

它什么时候会涨：池子里的某道题**在攻坚页里**最近一次作答是对的、且还没连满 3 次。

> ⚠️ **板块隔离之后这条变了**（2026-10-24 修正）：
> 原来三个数字读的是全局 `S.ans`，所以在顺序刷题里答对一次，攻坚页的「做对」也会涨。
> 现在 `drillStats` 只读 `ansAll.hard`，**在别的板块答对不会让这里的数字变化**。
> 这是「各板块各刷各的」的必然结果 —— 攻坚页只反映「你在这个专项里做得怎么样」。
>
> 但**掌握度（streak）仍然是全站共享的**：你在顺序刷题里连续答对 3 次，
> 这道题照样会从攻坚池里移出去。两个口径不一样，别混：
> · 概览卡三个数字 = 本板块记录
> · 是否出池 = 全站掌握度

一旦连满 3 次，题就出池了，也就从这个统计里消失了 ——
所以「做对」天生是个一闪而过的数字，它的意义是「正在巩固中的题有几道」，
而不是「我在这个专项里一共答对了多少题」。

顺带：`done` 同样只数池子内的题。攻坚池缩小之后「已做」的数字也会跟着变小，
看着像进度倒退，其实是池子换了 —— 想找真实累计，去「统计」页。

## 备份格式升到 v2：v1 会丢掌握度和成绩走势（2026-10-22）

给「三个专项练习」收尾时顺手查出来的一个真实缺陷，**已修复**。

### 缺陷是什么

`buildBackup()` 原来只导出这些字段：

```js
ans, wrong, star, wcnt, wlast, stats, memorizing
```

全是**错题本时代**的字段。可后面陆续加了 `streak`（掌握度）、`daily` /
`examHistory`（成绩走势）、`optRound`（选项轮次）、`pos` / `drill`（刷到第几题），
备份一个都没跟上。

后果在「换电脑」这个场景里特别狠 —— 而这正是备份功能存在的**唯一理由**：

| 导回来之后 | v1 的实际结果 |
|---|---|
| 连续答对数 `streak` | 全丢 → 所有「已掌握」的题变回未掌握 |
| 错题攻坚池 | 重新涨回去，昨天刚攻克的题又回来了 |
| 成绩走势页 7 天正确率 | 归零 |
| 考试历史柱状图 | 空 |
| 三个专项刷到第几题 | 全部回到第 1 题 |
| 选项排列轮次 `optRound` | 归零 → 选项位置整体换一套，和备份时看到的不一样 |

最气人的是它**不报错**：备份文件正常导出、正常导入、提示「已恢复备份：N 题记录」，
只有你自己去翻错题攻坚才发现「我明明攻下来的题怎么又出来了」。

### 怎么改的

1. `__version` 1 → 2，`data` 补齐 6 个字段：`streak` / `daily` / `examHistory` /
   `optRound` / `pos` / `drill`
2. 恢复侧逐个字段做类型校验和题目存在性过滤（`streak` 里挂的 gid 必须是本题库的题），
   **不是整个 `Object.assign` 一把梭** —— 后者会把脏数据原样吞进来
3. **向后兼容**：遇到 v1 旧备份，缺的字段保持导入前的当前值，不报错也不清零，
   所以以前导出的备份文件仍然能用
4. 恢复确认框多显示一行「已掌握：N 题」，让人一眼看出这份备份里有没有掌握度数据

### 顺带修掉的一个隐患

`buildBackup()` 返回的是 `S.ans` / `S.drill` 这些对象的**活引用**，不是副本。
`exportBackup()` 里紧接着就 `JSON.stringify`，所以一直没暴露；
但只要将来加个「先预览备份内容再导出」之类的东西，就会踩到
「看着预览、改了两笔进度、导出来的却是改后的数据」。

改法：加 `buildBackupSnapshot()` 做一次深拷贝，导出走它。
测试里专门留了一条断言：拿到快照后改 `S`，快照不能跟着变。

### 测试

`verify/verify_backup_restore.js` 从 26 项扩到 **45 项**，新增的重点是：

- v2 六个字段逐个断言「备份里有」**且**「导入后真的恢复出来了」
  —— 只测前者会漏掉「写了但导入时忘读」这类半截 bug
- v1 旧备份仍能导入、且不会把 `streak` / `daily` 弄成非法值
- `buildBackupSnapshot()` 确实是深拷贝

## 标签栏：从「横向滚动」改成「换行 / 网格」（2026-10-22）

### 问题

标签从 7 个涨到 12 个之后，窄屏放不下。原来的实现是：

```css
.tabs{display:flex;gap:7px;overflow-x:auto;scrollbar-width:none}
.tabs::-webkit-scrollbar{display:none}
```

行为是：**横向可滚动，但把滚动条藏起来了**。

手机上有手指可以左右划，所以看不出问题。但**电脑上鼠标滚轮不会横向滚动** ——
后面的「统计 / 成绩走势 / 错题排行 / 搜索」被切在视口外，既看不见、也点不到，
而且没有任何视觉线索提示「右边还有东西」。这是设计缺陷，不是显示 bug。

### 改法

**宽屏（≥700px）：6 列网格**

```css
@media (min-width:700px){
  .tabs{display:grid;grid-template-columns:repeat(6,minmax(0,1fr));gap:8px}
  .tab{min-width:0;padding:8px 4px;text-align:center;border-radius:10px}
}
```

12 个标签正好排成 2 行、每格等宽。
比 `flex-wrap:wrap` 好在不会出现「第一行挤 9 个、第二行只剩 3 个」的参差排布。

**窄屏：`flex-wrap:wrap` 自动换行** + 缩小字号内边距，实测 320/360/390px 都是 3 行。

### 两个必须记住的坑

**坑 1：`grid-template-columns: repeat(6,1fr)` 会被内容撑破**

默认是 `repeat(6, minmax(auto,1fr))`，`auto` 作为最小值意味着
「列宽不能小于内容宽度」。标签文字加上内边距要 74px，6 列就是 470px > 容器 349px，
于是整个文档横向溢出（实测 390px 屏，`document.scrollWidth` 变成 470）。

**必须写成 `minmax(0,1fr)`**，或者在 `.tab` 上加 `min-width:0`。
两个都写更保险（浏览器对 grid item 的 `min-width:auto` 处理有差异）。

**坑 2：换行后不能继续把标签栏放在吸顶 header 里**

`.bar`（进度条 + 标签）原来在 `<header>` 内部，而 header 是 `position:sticky`。
12 个标签换行成 2–3 行后，吸顶区高度从 148px 涨到 **230px**（390px 宽的手机上），
占掉屏幕近 1/3 —— 往下翻题时正文可看区域被吃掉太多，比原来更难用。

改法：把 `.bar` 挪到 `</header>` **外面**，成为 header 的兄弟节点。
滚动时标签栏会自然滚走，吸顶区只剩品牌 + 计时，高度回到 **98px**。
搬出来后 `.bar` 要补白底和底部分隔线，否则会透出下层内容。

### 顺带修的：计时条

`.clock` 原来也是 `overflow-x:auto` + 隐藏滚动条，同样的隐患（窄屏滚不动）。
改成 `flex-wrap:wrap`。但换行会把「平均 / 暂停」挤到第二行、多占 20px，
所以手机端把字号、间距收小，并隐藏竖分隔线（`.clock-sep`），让它稳定保持 1 行。

### 实测数据（真实 Chrome）

| 窗口 | 标签行数 | 标签栏高 | 吸顶 header 高 | 被裁标签 | 横向溢出 |
|---|---|---|---|---|---|
| 320px | 3 行 | 106px | 98px | 0 | 无 |
| 360px | 3 行 | 106px | 98px | 0 | 无 |
| 390px | 3 行 | 120px | 98px | 0 | 无 |
| 768px | **2 行** | 91px | 105px | 0 | 无 |
| 1280px | **2 行** | 91px | 105px | 0 | 无 |

改之前：390px 下吸顶 header 是 230px。

## 「查看答案」只影响单题 + 板块正确率（2026-10-22）

### 缺陷 1：点一次「查看答案」，整个题库永久变成背题模式

`reveal.onclick` 原来的写法是：

```js
S.memorizing = true;
save();          // ← memorizing 是全局且持久化的
```

`S.memorizing` 是顶部那个「背题」按钮的状态，**全局生效 + 写进 localStorage**。
于是点一次单题的「查看答案」，效果等于「整个题库、所有板块、直到你手动关掉为止，
全部直接显示答案和解析」，而且刷新浏览器还在。用户感受就是
「怎么默认不让我刷题了」。

`practiceCard()` 被 9 个板块共用（顺序、随机、错题本、收藏、搜索、三个专项），
所以这一处写错，全站一起中招。

改法：删掉全局开关，改成**单题临时揭示** `S.reveal[gid]`。

| 行为 | 结果 |
|---|---|
| 点「查看答案」 | 只 `S.reveal[当前 gid] = true` |
| 切到下一题 / 跳转 | `goto()` 里 `S.reveal = {}`，揭示不扩散 |
| 刷新浏览器 | **失效**（`save()` 故意不写 reveal，这是刻意的） |
| 顶部「背题」按钮 | 保持不变，仍是用户显式开启的全局开关 |
| 揭示后想继续作答 | 多一个「继续作答」按钮，删掉 reveal 并重置本题计时 |

`showAns` 现在有三个来源，优先级从高到低：
已作答 → 本题被揭示 → 全局背题模式。

### 缺陷 2：题卡头部看不到「这个板块我做得怎么样」

在「第 N / M 题」右边加一个小徽标：`正确率 75% 6/8`。

口径是**只统计当前板块题池内已作答的题**，所以每个板块看到的数字和自己做的范围一致：

| 板块 | 分母 |
|---|---|
| 顺序刷题 | 395 题里做过的 |
| 单选专项 | 273 题里做过的 |
| 多选专项 | 122 题里做过的 |
| 错题本 | 错题本里做过的 |
| 收藏 | 收藏里做过的 |
| 搜索 | 当前搜索结果里做过的 |

一道没做时 `total = 0`，**直接不渲染徽标** —— 显示「正确率 0%」会让人以为全错了。

实现是一个纯函数 `rateOfList(list)`，紧跟着 `.qidx` 插在同一个 flex 行里
（`.qhead` 本来就是 `flex-wrap:wrap`），所以不占额外一行、不影响任何原有布局。
真实浏览器截图确认过 390px / 1280px 下都不换行、不挤压题目。

## 键盘作答：四个真缺陷（2026-10-22）

页面一直宣称支持 `A`–`F` / `1`–`6` 选择、`Enter` 提交、`←` `→` 切题。
但「选项打乱」上线后，键盘这一路没跟着改，攒下了四个缺陷。
**它们全都只在键盘路径出现，鼠标路径是对的** —— 所以之前所有测试都没发现。

### 缺陷 1：按键映射错位（最严重）

存储层一律用**原始下标**，屏幕上是**显示位置**，换算只做在鼠标那条路径上：

```js
// 鼠标（正确）
b.onclick = function(){ submitNow(q, [oi]); };   // oi 是原始下标

// 键盘（错误）
var n = keyToIndex(e.key, q);   // n 是显示位置 0..5
submitNow(q, [n]);              // 直接当成原始下标用
```

选项打乱后，屏幕上 A 那一行对应的原始下标通常不是 0。4 个选项时
**约 3/4 的概率按 A 判的是别的选项** —— 用户看着 A 选下去，判分按 C 算。

改法：`toOrigIdx(keyToIndex(...), optionView(q).order)`，和鼠标走同一套映射。

考试路径同理，但要用**开考时固定的** `E.optOrder` 而不是现算，
否则考试中途改轮次会让按键和屏幕不一致。

### 缺陷 2：三个专项页键盘完全失效

键盘取当前题号用的是 `S.pos[S.mode]`。可专项模式的进度存在 `S.drill[key].pos` 里，
`S.pos.single` / `S.pos.multi` / `S.pos.hard` **根本不存在**，永远是 `undefined || 0 = 0`。

现象：

| 操作 | 期望 | 实际 |
|---|---|---|
| 在第 21 题按 `→` | 到第 22 题 | **被拽回第 2 题** |
| 在第 21 题按 `A` | 答第 21 题 | **答的是题池第 1 题** |

这和 README 前面记的「坑 2：题卡只认 `S.pos[modeKey]`」是同一个病根，
当时只修了渲染侧的 `getPos()` / `setPos()`，**键盘侧又写了一遍 `S.pos[S.mode]`**。
同一个状态只要还有第二个读写入口，就一定会漏 —— 这次是第二次漏。

改法：键盘里改成 `getPos(S.mode)`，并对越界做夹取。

### 缺陷 3：揭示答案后键盘还能作答

鼠标路径有 `if(showAns) return;` 挡着，键盘路径算 `showAns` 时漏了 `S.reveal`：

```js
var showAns = rec || S.memorizing;          // 漏了 reveal
```

于是答案已经摆在屏幕上了，按个 `A` 还能记一次作答（多半记成错）。
现在两处口径统一成 `rec || revealed || S.memorizing`。

### 缺陷 4：只读页面按键会偷偷改作答记录

交卷后 `examRunning()` 变 false，键盘逻辑继续往下跑，`modeList()` 落到 `QS`，
题号取 `S.pos.exam`（不存在）→ 0。结果：

> 在**成绩单**上随手按个字母，后台就把 `QS[0]` 答了一遍，还附赠错题计数 +1。

在「统计」「成绩走势」「错题排行」页也是一样。用户完全不知道发生了什么。

改法：加 `isPracticeMode(S.mode)` 前置判断，只有真正有题卡的练习页才响应键盘；
考试单独一个分支，其余页面直接 `return`。

### 一个测试工具上的坑（差点误判成产品 bug）

`shots_keyboard.js` 第一版用 CDP 这样派发方向键：

```js
await send('Input.dispatchKeyEvent', { type:'keyDown', key:'ArrowRight', text:'ArrowRight' });
```

真浏览器里**页面监听器根本收不到**，于是专项页方向键"没反应"，
看起来像缺陷 2 没修好。其实产品是对的 —— 方向键这类不产生字符的特殊键
必须用 `rawKeyDown` + `windowsVirtualKeyCode` / `nativeVirtualKeyCode`：

```js
const p = { key:'ArrowRight', code:'ArrowRight', windowsVirtualKeyCode:39, nativeVirtualKeyCode:39 };
await send('Input.dispatchKeyEvent', { type:'rawKeyDown', ...p });
await send('Input.dispatchKeyEvent', { type:'keyUp', ...p });
```

判断方法：在页面里挂一个监听器把 `e.key` 打出来。收到事件 = 派发方式的问题；
收不到 = 派发方式的问题；收到了但业务没反应 = 才是产品 bug。
这次是「先分清工具与产品的责任」，没有直接去改产品代码。

## 标签栏滚动行为：一次假阴性（2026-10-22）

上一轮留了个 `probe_scroll_fix.js`，判断写成：

```js
barScrolledAway = bar.bottom < header.bottom;
```

它一直报 ❌，看起来像「标签栏还压在吸顶区下面」。实际是**测量方法错了**：
题目页只有一道题，可滚距离常常只有 81–127px，而标签栏高 113–133px ——
页面根本滚不到「标签栏完全离开吸顶区」那个位置。

重写为 `probe_scroll_layout.js`，判断分三种：

| 情况 | 结论 |
|---|---|
| 完全滚出去了 | ✅ |
| 可滚距离 < 标签栏高度，且 `.bar` 不是 sticky | ➖ 滚不满属正常 |
| `.bar` 是 sticky / fixed | ❌ 会一直赖在吸顶区下面 |
| 滚够了但还压着 | ❌ 真的有重叠 |

6 种宽度（320 / 360 / 390 / 700 / 768 / 1280）实测：header 恒为 98–105px、
标签栏 2–3 行、`.bar` 是 `position:static`、无横向溢出、12 个标签一个都没被裁。

同时新增 `verify_scroll_layout.js`（28 项，跑在 jsdom 里）守住能静态验的部分：
`.bar` 必须是 header 的**兄弟节点**、不能是 sticky、标签栏不能用
`overflow-x:auto` 隐藏滚动条、网格必须 `minmax(0,1fr)`、12 个标签逐个可点。

分工和之前一致：**jsdom 验规则和结构，真浏览器验几何**。

## 模拟考试不能泄露对错（2026-10-22 修）

### 缺陷：考试中每选一个选项，当场就能知道自己对不对

题卡头部原来有一个实时估分：

```js
var scChk = el('span','qclock');
scChk.innerHTML = '约 <b>' + liveScore + '</b> 分';
scChk.title = '按已作答的题估算，未作答的题不计分';
```

`liveScore` 是「已作答且答对的题的分数和」。看着只是个参考数字，
但它实际上是**即时判卷**：

| 操作 | 「约 X 分」 |
|---|---|
| 选中一个错误选项 | 数字**不动** |
| 改成正确选项 | 数字**立刻 +1**（多选 +2） |

于是每答完一题瞄一眼分数，就知道该不该改答案 ——
模拟考试直接退化成「边考边对答案」，考不出真实水平。
多选题每题 2 分，数字在 0 / 2 之间跳，区分度更明显。

### 为什么不能「留着但藏起来」

先想过几个折中方案，都不成立：

| 方案 | 为什么不行 |
|---|---|
| 只在多选题隐藏 | 单选一样能反推 |
| 交卷前 5 分钟才显示 | 最后几题照样能用 |
| 做成 `display:none` 只藏 DOM | 打开控制台/切后台样式就看得见 |
| 显示「已答 30 题，得分 15-25 分区间」 | 区间端点仍会随单题对错跳变 |

结论：**考试期间不能存在任何与对错相关的数字**，只能给「题量 / 时间 / 分值」这类
与答案无关的信息。

### 改法

删掉 `liveScore` 那段，题卡头部只保留：

- 题型角标（单选题 / 多选题）
- 本题分值（`1 分` / `2 分`）—— 静态值，与对错无关
- 题号 `第 N / 75 题`
- 本题计时
- 已答 `x / 75`（只数「有没有选」，不数「对不对」）

顺带排查了其余所有可能泄露的通道，确认都不泄露：

| 通道 | 考试中是否泄露 | 说明 |
|---|---|---|
| 顶栏「已练 / 正确率」 | ❌ 不泄露 | `updateHeader` 只统计 `S.ans`，而考试作答存在 `E.ans`，交卷才合并 |
| 选项样式 | ❌ 不泄露 | 只有 `opt` / `opt sel`，没有 `ok` / `bad` / `locked` |
| 答案与解析块 | ❌ 不泄露 | 考试分支从不渲染 `.result` / `.ana` |
| 错题本角标 | ❌ 不泄露 | `noteWrong` 只在交卷时调（`finishExam` 里） |
| 正确率徽标 `.qrate` | ❌ 不泄露 | 只在 `practiceCard` 里渲染，考试走的是另一套卡片 |

### 交卷后照常

改的只是「考试进行中」，交卷后一切照旧：

两条路径的口径本来就不同，不要混。

## 板块隔离：各刷各的，但该汇总的仍然汇总（2026-10-22 重构）

### 用户报的问题

> 「每个板块都在单独刷，但一个板块刷了另一个板块也有记录，
> 比如我模拟考试考了，多选被选了，单选被选了，错题也有了」

### 根因：所有板块共用一份 `S.ans`

原来整个页面只有**一个**作答记录表 `S.ans`（gid → {sel, ok, t}），
九个板块都读写它。于是：

| 你做的事 | 实际后果 |
|---|---|
| 顺序刷题答 3 题 | 切到单选专项 → 那几题**显示「已作答」**，答案摊开、选项锁死 |
| 模拟考试交卷 | `finishExam` 把 **75 道题全并进 `S.ans`** → 顺序/随机/单选/多选**全部**「做过了」 |
| 模拟考试交卷 | 同时 `noteWrong` 每条错题 → 错题本一口气多几十道 |

第三行正是用户说的「错题也有了」。它有两个独立问题：
① 考试不该点亮练习板块；② 交白卷时 75 道「未作答」被一律判错、
全塞进错题本、错次全 +1，错题排行直接爆表。

### 现在的模型

一条主轴：**作答记录按板块分开存**
一条补充：**汇总类数据全站共享**

存储结构：

```js
S.ansAll = {
  seq:{gid:rec}, random:{gid:rec}, wrong:{gid:rec}, star:{gid:rec},
  search:{gid:rec}, single:{gid:rec}, multi:{gid:rec}, hard:{gid:rec}
}
```

所有读写收敛到四个函数（**不再有任何地方直接碰 `S.ansAll`**）：

| 函数 | 作用 |
|---|---|
| `boardKey(mode)` | 当前板块的存储键；考试等非练习板块返回 `null` |
| `boardAns(mode)` | 取某板块整张表 |
| `recOf(gid, mode)` / `setRec(...)` / `delRec(...)` | 读 / 写 / 删单条记录 |
| `aggregateAns()` | **只读汇总视图**：同一道题多板块做过时取最近一次 |

> 为什么坚持「只有一个读写入口」：前面记过这条教训（专项进度那次就是漏了第二个入口，
> 导致键盘读的还是旧变量）。这次一开始就把 35 处 `S.ans` 全部收敛到这四个函数。

### 哪些按板块、哪些汇总

| 数据 | 归属 | 理由 |
|---|---|---|
| 作答记录（对错、选了啥、用时） | **按板块** | 这就是「各刷各的」 |
| 刷到第几题 / 随机题序 | 按板块（原本如此） | 池子大小不同，共用会越界 |
| 题卡的正确率徽标 | **按板块** | 说的是「本板块做得怎么样」 |
| 专项概览卡（已做/对/错） | **按板块** | 同上 |
| 错题本 / 收藏 | **汇总** | 那是集合本身，不是某个板块的进度 |
| 累计错次 / 最近错于 | **汇总** | 错题排行按全站错次排序 |
| 掌握度 `streak` | **汇总** | 「这题我掌握了没有」不分在哪个板块练的 |
| 成绩走势 / 考试历史 | **汇总** | 历史事实 |
| 顶栏「已练 N 题 / 正确率」 | **汇总** | 整体进度，不该切个标签就跳一次 |
| 统计页 | **汇总** | 回答「整体学得怎么样」 |

一个容易搞混的点：**错题本和收藏既「汇总」又「有自己板块」**。
它们的**名单**是全站共享的，但你在「错题本」页里作答时，
记录写进 `ansAll.wrong`，不会回写到顺序刷题 —— 所以从错题本重刷一遍，
不会把顺序刷题的进度改掉。

### 考试的特殊规则

| 规则 | 为什么 |
|---|---|
| 考试作答只在 `S.exam.ans`，**不写任何板块** | 考试不是练习，不该点亮进度 |
| 答错的题**进错题本** | 用户明确要求；那是集合，不涉及进度 |
| **未作答的题不进错题本** | 交白卷不该塞 75 道「错题」，也会把错次统计搞乱 |
| 答题不进错题本（对的本来就该移除） | —— |

### 旧存档怎么办

老版本只有一份 `S.ans`，没法反推每题是在哪个板块做的。迁移策略：

- 全部记录归到**当前板块**（`d.mode`，不存在则 `seq`）
- 其余板块留空 —— 这样打开后不会又出现「所有板块都满了」，而那正是要修的毛病
- 备份文件同理：v3 存 `ansAll`，v2/v1 的 `ans` 按同一口径归位

代价要说清楚：**老用户升级后，原来的记录会集中到一个板块里**，
其他板块是从零开始的干净状态。这比「一打开全都满了」更符合预期。

### 测试

```bash
node verify/verify_board_isolation.js   # 54 项
node verify/shots_isolation.js          # 真实 Chrome：4 个场景 + 5 张截图
```

`verify_board_isolation.js` 覆盖：

- 数据结构（`ansAll` 存在、无 `S.ans`、8 个槽位）
- 一个板块作答 → 其他 7 个板块**一条记录都没有**，且题卡是可作答状态
- 隔离是双向的（专项 ↔ 顺序）
- 汇总口径：错题本/错次/掌握度/顶栏/统计页仍跨板块
- 考试：8 个板块全 0、错题进本、**未作答不进本**
- 备份 v3 字段，v2 旧备份形状识别
- 独立重置只清自己
- 旧存档迁移后只有 home 板块有记录

### 连带修掉的测试问题

这次重构让 **8 套旧测试**崩了 —— 它们全都直接读写 `S.ans`。修的时候踩到三个坑：

1. **批量正则替换把写入也改成了只读函数**
   `bank.S.ans[X] = {...}` → `bank.recOf(X) = {...}`（左值非法）。
   正则该写成两条：读用 `recOf`、写用 `setRec`。
2. **正则把方括号改坏**：`S.ans[pool[0].gid]` → `recOf(pool[0).gid]`，
   括号错位导致语法错误。批量替换后必须 `node --check` 逐个过一遍。
3. **板块归属写错**：测试在单选专项页准备数据，却写进了 `seq` 板块 ——
   于是「重置专项只清自己」这条根本验不到（数据压根不在那个板块）。
   这类错误**不会报错，只会静默地测了个寂寞**，比语法错误更难发现。

教训：批量替换只适合纯机械的改写；凡是涉及「这条数据属于哪个板块」的，
必须逐个看上下文手工确认。

## 对抗性审查：功能块之间的口径冲突（2026-10-24）

被要求「看看还有没有功能冲突、逻辑不对」。下面先把**每个功能块应该是什么逻辑**
写清楚，再逐条对照实现。四组审查里发现 5 个真缺陷。

### 一、先定各功能块的应然设计

| 功能块 | 它回答的问题 | 数据口径 | 生命周期 |
|---|---|---|---|
| 顺序 / 随机刷题 | 「按顺序过一遍」 | 各自独立记录 | 可逐板块重置 |
| 单选 / 多选专项 | 「专攻一种题型」 | 各自独立记录 | 可逐板块重置 |
| 错题攻坚 | 「把没掌握的错题歼灭」 | 池 = 错题本 ∪ (错过且未掌握) | **会自己变小** |
| 错题本 | 「我错过的题都在哪」 | **全站汇总的集合** | 答对 3 次自动移出 |
| 错题排行 | 「哪些题我反复错」 | 累计错次 `wcnt`，**只增不减** | 只在总重置时清 |
| 收藏 | 「我要反复看的题」 | 全站汇总 | 手动增删 |
| 模拟考试 | 「真实水平摸底」 | **完全独立**，不碰练习 | 每场独立 |
| 统计 / 成绩走势 | 「整体学得怎么样」 | **全站汇总** | 历史事实 |

**关键设计原则**（这是判断对不对的依据）：

1. **练习进度按板块隔离** —— 顺序刷题答过的题，到单选专项里应该是「没做过」
2. **错题是跨板块的全站事件** —— 不管在哪个板块错的，都进同一个错题本/排行/攻坚池
3. **「移出错题本」≠「已掌握」** —— 前者是「我不想看了」，后者要连续答对 3 次
4. **隔离的是「记录」不是「事实」** —— 掌握度、错次、成绩走势属于事实，全站共享

### 二、发现的缺陷

#### 缺陷 1：错题本「移出错题本」按钮根本没移出（按钮在说谎）

```js
rm.onclick = function(){
  noteRight(q.gid);        // ← 问题在这
  toast('已移出错题本');
}
```

`noteRight()` 内部只在 `streak >= 3` 时才真正 `splice` 掉。所以：

- 提示说「已移出错题本」→ 实际**一条都没删**
- 而且顺手把 `streak` +1（凭空多算一次答对）

| 实测 | 结果 |
|---|---|
| 错题本数量 | 57 → **57**（没变） |
| 该题还在错题本？ | **是** |
| streak | 0 → **1**（被误加） |

**修**：直接 `S.wrong.splice`，不碰 `streak`（掌握度只能靠真答对积累），
不碰 `wcnt`（历史错次是排行依据）。

> **按钮说谎比按钮没反应更糟** —— 用户以为处理过了，其实还在，下次又错一遍。

#### 缺陷 2：错题本里答对移出后，位置跳到别的题

`noteRight` 把题从 `S.wrong` 删掉后，数组短了一位，
但 `S.pos.wrong` 没跟着调整。用户正停在第 6 题，答对移出后
**位置不变 → 指向了原来的第 7 题**，看起来像「莫名跳题」；
停在最后一题时还会越界变空白。

**修**：删除点之前的 pos 不动，之后的 pos 前移一位，再夹回范围内。

#### 缺陷 3：统计页「累计错题」和错题本数量对不上

统计页用的是 `rankCount()`（`wcnt > 0` 的题数），而错题本页显示 `S.wrong.length`。
这两个数在两种情况下必然不一致：

- 用户点了「移出错题本」→ 名单清了，错次保留 → `rankCount` 仍算它
- 预置错题只有名单没有错次时（老版本问题）

**修**：统计页改成显示「错题本 = `S.wrong.length` 题」。
它想表达的是「我现在有多少道错题待处理」，那应该看名单；历史错次是排行页的事。

#### 缺陷 4：切板块时「本题计时」不归零，旧用时被叠加上去

`trackQuestion(gid)` 只在 gid 变化时归零。但**两个板块可能有同一道题**：
顺序刷题第 1 题和单选专项第 1 题就是同一道（单选池按题库顺序，第一道单选题就是她）。
于是切板块后 gid 没变 → 计时没归零，继续累加。

| 实测 | 结果 |
|---|---|
| 顺序刷题停了 2 秒后切到单选专项 | 本题计时显示 **2022ms**（应该是 ~0） |

**修**：切板块时置 `TMR.forceResetQ = true`，让下一次 `trackQuestion`
无条件归零。修完：2020ms → 0 → 1 秒后 1016ms。

#### 缺陷 5：题库源数据有 7 道「全对题」，练习时毫无提示

原始接口返回的 `IsAnswer` 里，7 道多选题的**所有选项都是 true**。
这导致：

- 练习时这道题唯一正确形态是「必须全选」，漏一个就错 —— 但页面完全看不出来
- 模拟考试里抽到这些题就是白送分（平均每场抽中 1.4 道）

这不是我们导出的 bug，是**源数据如此**（已核对 `topics_raw.json` 原始 `IsAnswer` 字段）。
之前 3 套测试间歇崩溃也是它引起的（`findIndex(o => !o.ok)` 返回 `-1`）。

**修**：练习页在题干下方加一句说明「这道题题库把全部选项都设为正确答案，
需要全选才算答对（源数据如此）」。**考试里不提示** —— 那是考试，不该给线索。

### 三、审查过但确认没问题的

| 检查项 | 结论 |
|---|---|
| 收藏板块答错是否进错题本 | ✅ 进（错题是全站事件） |
| 搜索板块答错是否进错题本 | ✅ 进 |
| 重做后答错，错次是否重复 +1 | ✅ 正常累加 |
| 连续答对 3 次是否真移出 | ✅ streak 0→1→2→3 时移出 |
| 攻坚池是否随掌握收缩 | ✅ 57 → 56 |
| 模考「放弃本次考试」 | ✅ `S.exam` 清空、不污染练习板块 |
| 考试成绩单逐题解析 | ✅ 只读，不写练习记录 |
| 考试是否重复计入练习统计 | ✅ 聚合已练数不增加 |
| 备份 v3 是否保持板块隔离 | ✅ seq/multi 各 1 条，没串 |
| 错题排行「点进去」跳转 | ✅ 在错题本走索引，不在则走搜索定位 |
| 多选未提交切走后 pend 残留 | ✅ 切回来自动恢复选中态（这是想要的） |
| 随机题序刷新后是否变 | ✅ 不变；重置才换 |
| 顺序刷题重置换选项排列 | ✅ 轮次 +1，排列确实变 |
| 专项重置是否误清掌握度 | ✅ 不清（清了攻坚池会回涨） |

### 四、仍然存在、但属于「设计取舍」的

| 现象 | 为什么保留 |
|---|---|
| 攻坚页「已做/做对/做错」只数本板块 | 与隔离一致；但池缩小时数字会变小，属预期 |
| 「移出」后错题本没了、排行还在 | 设计如此：移出≠掌握，历史错次是排行依据 |
| 总重置后预置的 57 道错题永久消失 | localStorage 已删，不会重新注入 |
| 错题排行定位不在错题本的题，用题干前 12 字搜索 | 可能命中多题，理论上不够精确（实测命中正确） |

### 五、一个文档与实现矛盾（已修）

README 原来写「在顺序刷题里重做对一次，攻坚页的『做对』也会涨」——
那是板块隔离**之前**的行为（当时读全局 `S.ans`）。
隔离后 `drillStats` 只读 `ansAll.hard`，别处答对不会影响它。
已在该节加注说明，并点明两个口径的区别：

- **概览卡三个数字** = 本板块记录
- **是否出攻坚池** = 全站掌握度

### 这一轮修掉的「测试自身的随机失败」

`verify_e2e_stats.js` 以前**约 20% 概率随机失败**，报「考试答错也计入错题次数」对不上。
根因不是产品：测试直接拿**原始下标**去点 `.opt`，而选项是打乱的，
于是「想点错」偶尔点成对的。修法和产品侧同一个道理 —— 先换算显示位置：

```js
const disp = bank.optionView(cur).order.indexOf(origIdx);
qa('.opt')[disp].click();
```

考试里则用 `E.optOrder[gid]` 换算。修完连跑 30 次全绿。

这和之前记的「随机是测试里的隐性输入」是同一条教训：
**凡是结果依赖随机（随机题、随机卷、随机选项排列），测试就必须先读出来再动手，
不能假设屏幕上第 i 个就是我想要的那个。**
